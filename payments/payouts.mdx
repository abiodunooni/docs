Payouts run on two different systems, and which one you use decides everything about how you build.

| | Basqet dashboard | Wallets API |
| --- | --- | --- |
| Where | Basqet dashboard | `openapi.quidax.io` |
| Bulk | CSV upload | Your own loop |
| Approval | Built into the flow | You build it |
| Effort | None | An integration |
| Best for | Occasional, finance-led runs | Automated, recurring, high volume |

<Note>
  There is no payouts API in Basqet. Everything programmatic runs on the [Wallets API](/wallets), which uses a different host, a different key and a different auth header from the rest of Payments.
</Note>

## From the Basqet dashboard

Your payout wallet is separate from your collection wallet. Fund it by settling collections into it, or receive directly: **Payout → Receive**, pick a currency, share the address.

## Through the Wallets API

One endpoint, and `fund_uid` decides the rail.

| `fund_uid` | Rail | Cost |
| --- | --- | --- |
| Blockchain address | On-chain | Network fee |
| Quidax account ID | Internal transfer | **Free, instant** |

<Warning>
  **Naira payouts are not available through the Wallets API.** Paying out to a Nigerian bank account is a dashboard action. For programmatic local currency payouts, use [Ramp off-ramp](/ramp/off-ramp).
</Warning>

### Types

```typescript
// Crypto only — naira payouts are dashboard-only, see the warning above.
type Currency = "usdt" | "usdc" | "btc" | "eth" | "trx" | "ltc";

interface WithdrawalRequest {
  currency: Currency;
  amount: string;              // decimal string, never a float
  fund_uid: string;            // blockchain address, or a Quidax account id
  reference: string;           // yours, unique, generated before the call
  fund_uid2?: string;          // destination tag, for chains that need one
  network?: string;            // required for multi-network assets
  narration?: string;
  transaction_note?: string;
}

interface Withdrawal {
  id: string;
  reference: string;
  type: "internal_transfer" | string;
  currency: Currency;
  amount: string;
  fee: string;
  total: string;               // what actually left the wallet
  txId: string | null;         // null for internal transfers
  status: "processing" | "done" | "rejected";
  reason: string | null;
}

interface Envelope<T> {
  status: "success" | "error";
  message: string;
  data: T | { code: string; message: string };
}
```

<Warning>
  Amounts are **decimal strings**, not numbers. Parsing `"0.0000000037183942"` into a JavaScript `number` loses precision silently. Keep them as strings end to end, and use a decimal library if you need arithmetic.
</Warning>

### A single payout

```typescript
const BASE = "https://openapi.quidax.io/exchange-open-api/api/v1";

async function quidax<T>(path: string, init: RequestInit = {}): Promise<T> {
  const res = await fetch(`${BASE}${path}`, {
    ...init,
    headers: {
      accept: "application/json",
      "content-type": "application/json",
      authorization: `Bearer ${process.env.QUIDAX_SECRET_KEY}`,
      ...init.headers,
    },
  });

  const body = (await res.json()) as Envelope<T>;

  if (body.status === "error") {
    const err = body.data as { code: string; message: string };
    throw new QuidaxError(err.code, err.message, res.status);
  }
  return body.data as T;
}

class QuidaxError extends Error {
  constructor(
    readonly code: string,
    message: string,
    readonly httpStatus: number,
  ) {
    super(message);
  }
  /** The withdrawal genuinely does not exist — safe to submit. */
  get isNotFound() { return this.code === "110112"; }
}
```

Check the balance and the network before you send:

```typescript
interface Wallet {
  balance: string;
  locked: string;
  staked: string;
  default_network: string | null;
  networks: Array<{
    id: string;
    name: string;
    deposits_enabled: boolean;
    withdraws_enabled: boolean;
  }>;
}

async function assertCanWithdraw(currency: Currency, network: string) {
  const wallet = await quidax<Wallet>(`/users/me/wallets/${currency}`);

  const net = wallet.networks.find((n) => n.id === network);
  if (!net?.withdraws_enabled) {
    throw new Error(`Withdrawals are disabled for ${currency} on ${network}`);
  }
  return wallet;
}
```

<Warning>
  Spendable balance is `balance` **alone**. `locked` is committed to open orders and pending withdrawals, `staked` is unavailable. Summing them will oversell the position.
</Warning>

Then submit:

```typescript
async function createWithdrawal(req: WithdrawalRequest): Promise<Withdrawal> {
  await assertCanWithdraw(req.currency, req.network!);
  return quidax<Withdrawal>("/users/me/withdraws", {
    method: "POST",
    body: JSON.stringify(req),
  });
}
```

<Warning>
  Always pass `network` for a multi-network asset. Omitting it falls back to the currency default, and a mismatch with the recipient's wallet loses the funds permanently.
</Warning>

### Resolving an uncertain outcome

The case that matters: you submitted, and you do not know whether it landed.

```typescript
async function resolve(reference: string): Promise<Withdrawal | null> {
  try {
    return await quidax<Withdrawal>(`/users/me/withdraws/reference/${reference}`);
  } catch (e) {
    if (e instanceof QuidaxError && e.isNotFound) return null; // never landed
    throw e;                                                   // unknown — do NOT resubmit
  }
}
```

<Warning>
  Only `110112` means it is safe to resubmit. Any other error means you still do not know, and resubmitting risks paying twice. Re-raise and let a human look.
</Warning>

### A resumable batch

There is no bulk endpoint. A batch is a loop, and the loop has to survive being interrupted.

```typescript
type RowState = "pending" | "submitted" | "done" | "failed";

interface PayoutRow {
  id: string;
  reference: string;       // deterministic: `${batchId}-${index}`
  address: string;
  amount: string;
  currency: Currency;
  network: string;
  state: RowState;
}

const RATE_LIMIT_MS = 250;   // ~240/min, inside the 300/min cap
const sleep = (ms: number) => new Promise((r) => setTimeout(r, ms));

async function runBatch(rows: PayoutRow[], db: Store) {
  // 1. Fail fast if the whole batch cannot be funded.
  const wallet = await assertCanWithdraw(rows[0].currency, rows[0].network);
  const total = rows.reduce((s, r) => s + Number(r.amount), 0);
  if (total > Number(wallet.balance)) {
    throw new Error(`Batch total ${total} exceeds balance ${wallet.balance}`);
  }

  for (const row of rows) {
    if (row.state === "done" || row.state === "failed") continue;

    // 2. Anything already submitted is resolved, never resubmitted blindly.
    if (row.state === "submitted") {
      const existing = await resolve(row.reference);
      if (existing) {
        await db.update(row.id, { state: "done" });
        continue;
      }
    }

    // 3. Mark BEFORE the call, so a crash mid-flight is recoverable.
    await db.update(row.id, { state: "submitted" });

    try {
      await createWithdrawal({
        currency: row.currency,
        amount: row.amount,
        fund_uid: row.address,
        network: row.network,
        reference: row.reference,
      });
      await db.update(row.id, { state: "done" });
    } catch (e) {
      if (e instanceof QuidaxError && e.isNotFound) {
        await db.update(row.id, { state: "pending" }); // safe to retry next run
      } else {
        await db.update(row.id, { state: "failed", reason: String(e) });
      }
    }

    await sleep(RATE_LIMIT_MS);
  }
}
```

The three properties that make this safe:

1. **Deterministic references.** `${batchId}-${index}` means re-running the same batch cannot double-pay — the second attempt resolves each reference and finds it already landed.
2. **Mark before the call.** A crash between the request and the response leaves the row `submitted`, which the next run resolves rather than resubmits.
3. **Never invent a new reference.** A failed lookup that is not `110112` means "unknown", and unknown must never become "retry".

<Warning>
  Random per-run references defeat all of this. A re-uploaded file pays everyone a second time, and an on-chain payout cannot be recalled.
</Warning>

### Ingesting a CSV yourself

Validate the whole file before submitting anything. Half a payroll is worse than none.

```typescript
function validateBatch(rows: PayoutRow[], wallet: Wallet): string[] {
  const errors: string[] = [];
  const seen = new Set<string>();

  for (const [i, r] of rows.entries()) {
    if (!r.address?.trim())            errors.push(`row ${i}: missing address`);
    if (!(Number(r.amount) > 0))       errors.push(`row ${i}: invalid amount`);
    if (seen.has(r.address))           errors.push(`row ${i}: duplicate recipient`);
    seen.add(r.address);
  }

  const total = rows.reduce((s, r) => s + Number(r.amount), 0);
  if (total > Number(wallet.balance)) {
    errors.push(`total ${total} exceeds balance ${wallet.balance}`);
  }
  return errors;
}
```

Then show a human the recipient count, the total per currency, and the largest single payout — and require an explicit approval before `runBatch` is allowed to start.

### Reconciling

Mark rows complete on `withdraw.successful` and failed on `withdraw.rejected`, keyed on `reference` and processed idempotently.

## Refunds

Refunds are not self-serve in the Basqet dashboard. An agreed refund is processed as a payout to the customer's wallet.

Set `refund_address` when you initiate a transaction, so the destination is captured at payment time rather than negotiated in a support thread.
