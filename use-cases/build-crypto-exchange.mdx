You build the product and own the customer. Quidax provides the accounts, custody, liquidity and settlement underneath.

| You build | Quidax provides |
| --- | --- |
| Interface, onboarding, your ledger | Sub-accounts and custody |
| Pricing and fees you add | Order book liquidity and execution |
| Support and compliance workflows | Blockchain addresses and monitoring |

**Products:** [Wallets](/wallets) for accounts and custody, [Order Book](/wallets/trading) for execution, [Ramp](/ramp) if you want local-currency funding.

## Build it

<Steps>
  <Step title="Create a sub-account per user">
    `POST /users` with your internal user ID in `reference`.

    **You get back** an `id` — the `user_id` for every later call. Store it against your user.

    <Card title="Sub-accounts" icon="users" href="/wallets/sub-accounts" horizontal />
  </Step>

  <Step title="Generate deposit addresses on demand">
    `POST /users/{user_id}/wallets/{currency}/addresses?network=trc20`

    Generate lazily, when a user first asks to deposit that currency. Generating for every user in every currency up front hits the 20-per-second limit for no benefit.

    **Expect** `wallet.address.generated` if the address is not in the response — generation is asynchronous for some currencies.

    **Check first:** `GET /users/{user_id}/wallets/{currency}` tells you whether the currency is receivable at all and which networks have `deposits_enabled`.
  </Step>

  <Step title="Credit deposits at ACCEPTED, never earlier">
    **Expect** `deposit.transaction.confirmation`, then `deposit.successful`.

    Re-query and credit only when `status` is `ACCEPTED`. A deposit confirmed on-chain can still be held or fail AML screening.

    ```typescript
    interface Deposit {
      id: string;
      currency: string;
      amount: string;
      status: string;           // lowercase in payloads, uppercase in the tables
      wallet: { user: { id: string; reference: string | null } };
    }

    export async function onDepositWebhook(event: { data: Deposit }) {
      // 1. The webhook says something happened. The API says what is true now.
      const deposit = await quidax<Deposit>(
        `/users/${event.data.wallet.user.id}/deposits/${event.data.id}`,
      );

      if (deposit.status.toUpperCase() !== "ACCEPTED") return;

      // 2. Credit exactly once, keyed on the deposit id.
      await db.transaction(async (tx) => {
        const claimed = await tx.insertIfAbsent("processed_deposits", {
          deposit_id: deposit.id,
        });
        if (!claimed) return;                       // already handled

        await tx.creditLedger({
          userRef: deposit.wallet.user.reference,
          currency: deposit.currency,
          amount: deposit.amount,                   // keep as a string
        });
      });
    }
    ```

    <Warning>
      The idempotency claim and the ledger credit must be in **one transaction**. Insert-then-credit across two calls leaves a window where a retry credits twice.
    </Warning>
  </Step>

  <Step title="Show prices">
    `GET /markets/tickers` for the whole board, `GET /markets/tickers/{market}` for one pair.

    Use tickers for display. Order book and depth are much heavier responses — reach for them only when building a trading view or calculating slippage.
  </Step>

  <Step title="Place orders">
    `POST /users/{user_id}/orders`

    **Round to the pair's precision first**, and check the minimum. These two rules cause most rejections.

    ```typescript
    const PRECISION: Record<string, { volume: number; price: number }> = {
      btcusdt: { volume: 5, price: 2 },
      ethusdt: { volume: 4, price: 2 },
      usdtngn: { volume: 2, price: 2 },
    };

    function floorTo(value: string, dp: number): string {
      // floor, never round up — rounding up can exceed the user's balance
      const [i, f = ""] = value.split(".");
      return dp === 0 ? i : `${i}.${f.padEnd(dp, "0").slice(0, dp)}`;
    }

    export async function placeOrder(userId: string, o: {
      market: string;
      side: "buy" | "sell";
      ord_type: "limit" | "market";
      volume: string;
      price?: string;
    }) {
      const p = PRECISION[o.market];
      if (!p) throw new Error(`Unknown precision for ${o.market}`);

      return quidax(`/users/${userId}/orders`, {
        method: "POST",
        body: JSON.stringify({
          ...o,
          volume: floorTo(o.volume, p.volume),
          price: o.price ? floorTo(o.price, p.price) : undefined,
        }),
      });
    }
    ```

    **Expect** `order.done` when it executes. An order can fill across several trades — reconcile against `GET /users/{user_id}/trades`, not the order alone.

    <Card title="Trading" icon="chart-candlestick" href="/wallets/trading" horizontal />
  </Step>

  <Step title="Let users withdraw">
    `POST /users/{user_id}/withdraws` with a pre-generated unique `reference` and an explicit `network`.

    **Expect** `withdraw.successful` or `withdraw.rejected`.

    There is no address-validation endpoint, so validate format client-side before submitting.
  </Step>

  <Step title="Sweep to treasury">
    Internal transfers to your parent account are instant and free — set `fund_uid` to the destination account ID rather than an address.
  </Step>
</Steps>

## Decisions to make early

<AccordionGroup>
  <Accordion title="Where your ledger lives" icon="book">
    Quidax holds balances, but your product still needs its own ledger for pending states, your fees, and anything Quidax does not know about.

    Treat Quidax as the truth for what settled, and your ledger as the truth for what you told the customer. Reconcile on a schedule so a missed webhook surfaces in hours, not at month end.
  </Accordion>

  <Accordion title="Local currency funding" icon="money-bill-transfer">
    Wallets does not take fiat pay-ins. If users should fund in naira or cedis, add [Ramp](/ramp) — either the widget, where Quidax verifies each user, or the API, where you do under your own licence.
  </Accordion>

  <Accordion title="Which assets you list" icon="list-check">
    Several supported assets are **trade-only** — they cannot be sent, received, or given an address. Never offer a deposit flow for one.

    <Card title="Coverage and limits" icon="globe" href="/wallets/coverage" horizontal />
  </Accordion>

  <Accordion title="Custody is regulated" icon="scale-balanced">
    Holding customer funds is a licensed activity in most markets. Confirm your position during onboarding before you build.
  </Accordion>
</AccordionGroup>
