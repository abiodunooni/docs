Every request authenticates with a secret key sent as a bearer token.

```bash
curl 'https://openapi.quidax.io/exchange-open-api/api/v1/users/me' \
  -H 'accept: application/json' \
  -H "Authorization: Bearer $QUIDAX_SECRET_KEY"
```

## Getting a key

<Steps>
  <Step title="Open API management">
    Log in to your merchant account, click your username in the navigation bar, then the user icon. Open the **API management** tab.
  </Step>

  <Step title="Create the key">
    Enter an IP address if you want to restrict the key, provide your authentication code, and click **Create**.
  </Step>

  <Step title="Store it">
    Copy the key into your server's secrets store. Treat it like a password.
  </Step>
</Steps>

<Tip>
  Restricting a key to your server's IP address is the single cheapest security measure available here. A leaked key that only works from one address is far less damaging than one that works from anywhere.
</Tip>

<Warning>
  The secret key is server-side only. It grants full access to your account and every sub-account under it, including withdrawals. Never ship it in browser or mobile code, never commit it, and never log it.
</Warning>

## Always use HTTPS

Non-TLS requests return a `301`. Beyond failing, a plain HTTP request leaks your key in transit — treat any key sent over HTTP as compromised and rotate it.

## Rate limits

| Endpoint | Limit |
| --- | --- |
| Address generation (`POST .../wallets/{currency}/addresses`) | 20 requests per second |
| Everything else | 300 requests per minute |

Exceeding a limit returns **`444`**. Build a retry with backoff around that status, and queue bulk work rather than firing it all at once.

<Note>
  `444` is non-standard, so some HTTP clients and proxies handle it oddly. Check your client surfaces it rather than treating it as a connection error.
</Note>

## Accounts and scope

One key covers your whole account tree. Endpoints take a `user_id` path segment that decides which account you are acting on:

| Value | Acts on |
| --- | --- |
| `me` | Your parent account |
| A sub-account's user ID | That sub-account |

<Warning>
  Because one key reaches every sub-account, a compromised key exposes all your customers' funds, not just your own. Rotate immediately if you suspect exposure.
</Warning>
