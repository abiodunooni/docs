The API follows normal REST patterns — resource-oriented URLs, JSON bodies and responses, standard verbs and status codes.

## Base URL

```
https://openapi.quidax.io/exchange-open-api/api/v1
```

<Warning>
  Older code samples in circulation use `https://www.quidax.com/api/v1` and `https://app.quidax.io/api/v1`. Use the `openapi.quidax.io` host above — if you have the others hard-coded anywhere, migrate them.
</Warning>

## Response format

Every response uses the same envelope.

```json
{
  "status": "success",
  "message": "Successful",
  "data": { }
}
```

Errors use the same shape, with a machine-readable code nested inside `data`.

```json
{
  "status": "error",
  "message": "Invalid secret key.",
  "data": {
    "code": "E0001",
    "message": "Invalid secret key."
  }
}
```

<Tip>
  Branch on `data.code`, not on `message`. Messages are written for humans and get reworded; codes are stable.
</Tip>

### Error codes

| Code | Meaning |
| --- | --- |
| `E0001` | Invalid secret key. |
| `E0104` | The sub-account does not exist. |
| `E0107` | Validation failed. The message names the offending field. |
| `E0605` | A currency value is not valid. |
| `110112` | The withdrawal with that reference does not exist. |

<Note>
  This list covers the codes visible in the current examples and is not exhaustive. Handle unknown codes gracefully rather than assuming you have seen them all.
</Note>

## Pagination

List endpoints return a subset of results per call. Control the page size with `per_page`.

| Parameter | Default | Maximum |
| --- | --- | --- |
| `per_page` | 50 | 100 |

Paginated responses carry these headers:

| Header | Meaning |
| --- | --- |
| `x-page` | Current page number |
| `x-per-page` | Records returned per page |
| `x-total-pages` | Total pages available for this request |
| `x-next-page` | Cursor or page value for the next set. **Empty means you have reached the end.** |

<Tip>
  Loop until `x-next-page` is empty rather than counting up to `x-total-pages`. Records can be added while you paginate, and the cursor handles that correctly where a page counter does not.
</Tip>

## Errors

| Code | Status | Meaning |
| --- | --- | --- |
| `400` | Bad request | Something in the request is wrong or missing. |
| `401` | Unauthorized | The key is invalid or does not exist. |
| `403` | Forbidden | The key lacks permission for this operation. |
| `404` | Not found | The resource does not exist. |
| `429` | Too many requests | You are over a rate limit. |
| `444` | Rate limited | Returned by the rate limiter. Back off and retry. |
| `5xx` | Server error | Something went wrong on our side. Retry. |

## Transaction statuses

<Tabs>
  <Tab title="Deposits">
    | Status | Meaning |
    | --- | --- |
    | `SUBMITTING` | Being submitted. |
    | `SUBMITTED` | Submitted and awaiting processing. |
    | `ON_HOLD` | Held for review. |
    | `CHECKED` | Checks completed. |
    | `ACCEPTED` | Confirmed and credited. |
    | `CANCELED` | Cancelled before completion. |
    | `REJECTED` | Rejected. |
    | `FAILED` | Failed. |
    | `FAILED_AML` | Failed anti-money-laundering screening. |

    <Note>
      Only `ACCEPTED` means the funds are credited and yours to give value against. Everything else is in flight or has stopped.
    </Note>
  </Tab>

  <Tab title="Withdrawals">
    | Status | Meaning |
    | --- | --- |
    | `PROCESSING` | Being processed. |
    | `DONE` | Completed. |
    | `REJECTED` | Failed. |
  </Tab>

  <Tab title="Orders">
    | Status | Meaning |
    | --- | --- |
    | `WAIT` | Queued for execution. |
    | `DONE` | Executed. |
    | `CANCEL` | Cancelled. |
  </Tab>
</Tabs>

## Minimum order values

| Currency | Minimum |
| --- | --- |
| NGN | 1,000 |
| USDT | 0.90 |

Anything below throws an error, so validate in your own interface before submitting.

## Precision
