## What is shared

<Columns cols={2}>
  <Card title="Credentials per platform" icon="key">
    Products sit on three platforms, each with its own dashboard, API keys and webhook configuration. Keys are never interchangeable between them.
  </Card>

  <Card title="Server-side secrets" icon="shield-check">
    Secret keys authenticate API calls and sign webhooks. They belong on your server only. Public keys, where a product has one, are the only credentials safe in a client.
  </Card>

  <Card title="Webhooks as source of truth" icon="webhook">
    Treat the webhook as the authority on final state, verify its signature, respond `2xx` quickly, and process idempotently.
  </Card>

  <Card title="Your own references" icon="hashtag">
    Send a unique reference of your own on every transaction, and store the Quidax identifier that comes back. Reconciliation and support both depend on having the pair.
  </Card>
</Columns>

<Warning>
  Because each platform issues its own credentials, name your environment variables by platform — `RAMP_SECRET_KEY` rather than `API_KEY`. Mixing keys between platforms is the most common cause of a `403` that looks inexplicable.
</Warning>

## What differs

| | Host | Authentication | Sandbox |
| --- | --- | --- | --- |
| Ramp | `ramp-be.quidax.io` | `x-private-key` header | No, test in production |
| Payments | Basqet platform | Per-platform credentials | Yes, full sandbox |
| Wallets | Quidax business platform | Per-platform credentials | No, test in production |
| Orderbook | Quidax business platform | Per-platform credentials | No, test in production |

Wallets and Orderbook share one business account, so one set of keys covers both.
